# Atlas Notes transfer schema v1 (for future Windows receiver)

The phone produces a ZIP archive using the ZIP **stored** method (no compression). This makes the package easy to read using standard tooling without online dependencies.

The archive contains `manifest.json` and `photos/<note UUID>/<photo UUID>.<ext>` attachments.

Example manifest:

```json
{
  "format": "atlas-notes-transfer",
  "schemaVersion": 1,
  "applicationVersion": "0.1",
  "batchId": "<UUID>",
  "exportedAt": "<ISO-8601>",
  "photoQuality": "optimized",
  "notes": [
    {
      "id": "<UUID>",
      "title": "Example",
      "body": "Captured observation",
      "createdAt": "<ISO-8601>",
      "updatedAt": "<ISO-8601>",
      "attachments": [
        {
          "id": "<UUID>",
          "originalName": "image.heic",
          "path": "photos/<note-id>/<photo-id>.jpg",
          "mimeType": "image/jpeg",
          "bytes": 123456,
          "sha256": "<lowercase SHA256 hex of attachment bytes>",
          "quality": "optimized"
        }
      ]
    }
  ]
}
```

The Windows receiver MUST:

1. Validate `format`, `schemaVersion`, note UUIDs, attachment paths, attachment lengths, and every SHA-256 hash. Reject ZIP path traversal and other unsafe archive entries.
2. De-duplicate records by note ID and its exact `updatedAt` revision; never silently replace later edits.
3. Save notes/photos to durable desktop storage, flush to disk, and ensure they are visible in the desktop Quick Notes Inbox. On failure do not generate an acknowledgment.
4. Only after a successful, durable import, issue a receipt using the schema below. The receipt includes the SHA-256 of the WHOLE original ZIP and each imported note's ID + revision.
5. Never include a not-yet-imported note in `importedNotes`.

Receipt schema (generated by the Windows importer):

```json
{
  "format": "atlas-notes-import-receipt",
  "schemaVersion": 1,
  "status": "imported",
  "batchId": "<export manifest batchId>",
  "archiveSha256": "<lowercase SHA256 hex of original ZIP>",
  "importedNotes": [
    {"id": "<note UUID>", "updatedAt": "<ISO-8601>"}
  ]
}
```

On receipt import, the iPhone verifies matching export batch and ZIP hash, checks every note ID+revision belongs to that batch, and then asks for confirmation before removing matching unchanged notes/photos. Notes edited after ZIP creation are retained.

**No Windows importer ships with prototype v0.1.** The phone's receipt reader is a safety mechanism awaiting that companion implementation.
